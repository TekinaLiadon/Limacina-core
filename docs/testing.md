# Тесты

## Режимы прогонов

| Команда                     | Что гоняет                                                 | Когда                        |
| --------------------------- | ---------------------------------------------------------- | ---------------------------- |
| `bun run test:unit`         | всё, кроме e2e и тестов с реальной БД                      | в работе над задачей, быстро |
| `bun test src/<модуль>/...` | файлы текущей задачи                                       | там же, точечно              |
| `bun run check-all`         | типы, формат, все тесты, линт, покрытие, случайный порядок | перед релизом                |
| `bun run test:randomize`    | все тесты со случайным порядком                            | входит в check-all           |
| `bun run test:flows`        | сквозные сценарии против реального приложения и БД         | вручную при дев-БД           |

CI в том же порядке, что и check-all: типы, формат, тесты, линт, гейт покрытия, randomize.

## Независимость

Все тесты проходят в любом порядке, это гейтится randomize-прогоном. Bun исполняет тестовые файлы в одном процессе, поэтому module-level состояние живёт между файлами. Отсюда правила:

- сид-данные в `beforeAll` уровня файла, каждый тест либо читает сид, либо создаёт свои данные.
- мутации общего состояния (бан, approve, пароль, роль) откатываются в `finally`, откат случается и при упавшем ассерте.
- ассерты на списки относительные (`toContain`, `toBeGreaterThan`), а не точные снимки.
- `mock.module()` не используется: подмена живёт до конца процесса и отравляет другие файлы, вместо него DI (зависимость передаётся конструктором и мокается инстансом).
- лимитные тесты изолируют username и IP (свой юзер на describe, свои `X-Forwarded-For`).
- тяжёлые локальные фикстуры (`public/`, `config.toml`) в CI отсутствуют: тесты их либо создают сами, либо скипают по `existsSync`.

## Хелперы

- `setupTestEnv()` (`src/utils/tests/test-env.ts`): канонический тестовый env для каждого файла, специфичные переменные задаются после него.
- `installFakeSqlClient()` (`src/utils/tests/sql-fake.ts`): юниты SQL-сторов без реальной БД, фейковый клиент отвечает заготовленными строками на каждый запрос.
- `postgresDescribe` (`src/utils/tests/postgres-suite.ts`): интеграционные наборы против `DATABASE_URL`, без переменной весь набор скипается, поэтому CI без базы зелёный.
- `contractDescribeEach` (`src/utils/tests/driver-contract.ts`): одни ассерты против map и postgres реализаций стора, расхождение драйверов валит оба кейса.
- `applyV1ApiPrefix` (`src/utils/tests/v1-prefix.ts`): для сьютов, объявляющих v1-контроллеры мимо V1Module.

## База для интеграционных

```bash
docker run -d --name Limacina -p 5432:5432 -e POSTGRES_USER=Limacina -e POSTGRES_PASSWORD=Limacina postgres:14
bun run migrate:up
bun test
```

`DATABASE_URL` в `.env` задаёт базу. Тесты создают пользователей с префиксами (`pgauth_`, `pgadm_`) и чистят за собой, но база общая с сервером: только дев-база, не прод. Контрактные и интеграционные наборы работают и на MariaDB (та же `DATABASE_URL` с `mariadb://`), миграции при этом postgres-only.

## Флоу-тесты

`bun run test:flows` проигрывает пользовательские джорни поверх реального приложения: харнесс поднимает его функцией `bootstrap()` на порту 0 над одноразовой базой `limacina_flow_<PID>` (DROP, CREATE, миграции), каждый файл бежит отдельным процессом, независимые файлы параллельно пулом.

Файлы в `src/e2e/flows/`: бутстрап владельца, сессия лаунчера, запуск игры через Yggdrasil, скин (загрузка лаунчером видна в игре), модерация панели, удаление и восстановление, релизы лаунчера.

Без `DATABASE_URL`, при непостгресовом или нелокальном хосте, а также с `SKIP_FLOW_TESTS=1` наборы скипаются. Гард отсекает и случайный запуск против продовой базы: хост обязан быть localhost. Покрытие этим прогоном не собирается.

## Покрытие

Порог 95% общих линий, гейт: `bun run coverage:gate` по `coverage/lcov.info`. Покрытие пишется при каждом `bun test`. Исключения из подсчёта (`coveragePathIgnorePatterns` в `bunfig.toml`) точечные: прокси-заглушка стора и pino-инфраструктура лог-потока.

Нюанс: без `DATABASE_URL` постгрес-сторы остаются непокрытыми и гейт красный. Это осознанно: в CI гейт не гоняется, локально база задана всегда. Порог двигается только вверх, исключение из подсчёта требует обоснования.
