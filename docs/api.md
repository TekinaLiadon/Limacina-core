# API

## Где смотреть спецификацию

Спецификация генерируется из кода, декораторами `@nestjs/swagger` на контроллерах и DTO. Она не может устареть: правка эндпоинта или DTO сразу меняет спеку.

- `/docs`: Scalar UI, просмотр спеки с возможностью выполнить запрос прямо из браузера.
- `/openapi.json`: машинный OpenAPI-документ. Годится для кодогенерации клиентов и импорта в Postman.

Списка эндпоинтов в этой документации нет намеренно, дублировать генерируемую спеку незачем. Ниже то, чего в спеке не видно: доступ, лимиты, формат ошибок.

## Группы маршрутов

Все актуальные маршруты живут под префиксом `/v1`. Теги в спеке совпадают с URL-группами:

| Тег               | Что там                                                                                | Доступ                      |
| ----------------- | -------------------------------------------------------------------------------------- | --------------------------- |
| `common_auth`     | регистрация, логин, refresh, invalidate, смена пароля                                  | публичный                   |
| `common_content`  | скины, плащи, модели                                                                   | JWT                         |
| `common_status`   | онлайн игрового сервера                                                                | публичный                   |
| `launcher_update` | latest.json и релизы tauri-plugin-updater                                              | публичный                   |
| `launcher_files`  | манифест файлов игры и моды                                                            | публичный                   |
| `launcher_config` | config.toml на чтение                                                                  | публичный                   |
| `panel_users`     | пользователи: списки (с ID установок лаунчера), approve, ban, роли, пароли, init-owner | admin, часть действий owner |
| `panel_logs`      | чтение логов сервера                                                                   | admin                       |
| `panel_launcher`  | запись лаунчера: релизы, конфиг, моды                                                  | owner                       |
| `panel_server`    | рестарт, rebuild, RCON-консоль                                                         | owner                       |
| `yggdrasil`       | протокол authlib-injector                                                              | протокольная авторизация    |

Исключение из префикса одно: `yggdrasil`. Пути `/authserver/*`, `/sessionserver/*`, `/api/*` и метадата на `GET /` продиктованы authlib-injector и живут в корне сервера. Новые эндпоинты проекта добавляются только под `/v1`.

## Авторизация запросов

Bearer-токен в заголовке `Authorization`, в спеке он объявлен как security scheme `bearer`. Где брать токены:

- Панель и лаунчер: пара из `POST /v1/common/auth/login`, access живёт 3 часа.
- Текстуры по протоколу Yggdrasil: accessToken из `POST /authserver/authenticate`.

Роли четыре: `user`, `moderator`, `admin`, `owner`, каждая выше предыдущей. Гард сравнивает веса, поэтому owner проходит везде, где требуется admin, а маршрут с `@Roles("owner")` модератору и админу закрыт. Роль владельца передаётся отдельным эндпоинтом (`PATCH /v1/panel/users/owner`), через смену роли её не назначить. Мутации пользователей дополнительно проверяют иерархию: вызывающий строго выше цели, выдаваемая роль тоже строго ниже собственной.

Каждый не-`@Public()` запрос проходит через JWT-стратегию, которая заодно проверяет, что пользователь жив, одобрен, не забанен и не сменил пароль после выдачи токена.

## Формат ошибок

Тело ошибки это `{ statusCode, message }`. Сообщения валидации на русском, формат "поле: правило" (пример: "username: минимум 3 символа"). На 500 тело всегда "Internal Server Error", внутренние детали утекать не должны, зато полностью пишутся в лог. Rate limit отвечает 429 с заголовком `Retry-After` и текстом "Повторите через N с.". Протокольные ошибки Yggdrasil (`ForbiddenOperationException` и родня) англоязычные, как требует authlib-injector.

## Лимиты

- Глобальный: 600 запросов с одного IP за минуту на все маршруты (`RATE_LIMIT_GLOBAL_MAX`, `RATE_LIMIT_GLOBAL_WINDOW`).
- Auth-маршруты: два бака сразу, по username и по IP, по 10 попыток за окно. Username-бакет покрывает логин, регистрацию и `POST /authserver/signout`, смена пароля бьёт в бакет по хешу Bearer-токена. 429 приходит при исчерпании любого бака, перебор с ротацией имён отсекает IP-бакет.
- `POST /authserver/authenticate` от username-бакета освобождён сознательно (решение проекта, закреплено в исключениях), глобальный IP-лимит на него действует.

Значения и окна настраиваются env-переменными, полный список в [setup.md](setup.md).

## Валидация входа

Глобальный `ValidationPipe` работает с `transform` и `whitelist`: лишние поля тела срезаются, а не игнорируются молча. Параметры маршрутов с перечислимыми значениями (например `skin` или `cape` в текстурах) проверяются пайпами, типы TypeScript рантайм не валидируют. Длинные списки (`batch-profiles`, пагинация) имеют жёсткие границы: 10 имён на батч, лимит страницы задаёт каждый маршрут свой.
