# Архитектура

## Стек

NestJS 11 с адаптером Fastify, рантайм Bun 1.4.x (не Node). Типы проверяет tsgo, линтер oxlint, форматтер oxfmt, тесты bun:test. `bun run build` собирает самодостаточный бинарник `dist/Limacina`.

Точка входа `src/main.ts`. Функция `bootstrap()` собирает приложение и возвращает его, а сам запуск защищён `import.meta.main`. Поэтому e2e-тесты поднимают тот же AppModule в своём процессе, без отдельного сервера.

На старте `main.ts` регистрирует в Fastify:

- статику из `public/` и SPA панели на `/panel` (маршрут есть всегда, каталог создаётся при отсутствии, поэтому панель деплоится без рестарта),
- CORS, закрытый полностью, если `CORS_ORIGINS` не задан,
- `@fastify/multipart` с лимитом размера файла,
- два rate limit: глобальный по IP на все маршруты и отдельный на auth-эндпоинты,
- обработчики `/docs` (Scalar UI) и `/openapi.json`.

## Путь запроса

1. Rate limit на Fastify-хуках, 429 с заголовком `Retry-After` при исчерпании.
2. Глобальный гард `Jwt_authGuard`: валидирует access-JWT, пропускает маршруты с `@Public()`.
3. Глобальный гард `RolesGuard`: проверяет `@Roles()`. Роли взвешены, owner проходит туда, где требуется admin. Опечатка в названии роли запрещает доступ всем, а не никому.
4. Глобальный `ValidationPipe` (transform + whitelist): DTO на class-validator, лишние поля срезаются, сообщения на русском.
5. Контроллер `src/v1/`: тонкий транспортный слой, парсит вход и зовёт доменный сервис.
6. Доменный сервис (`src/auth`, `src/admin` и другие) и стор (`*_store.ts`) или файловая система.

Доменная логика в v1-контроллерах не живёт. Все маршруты собираются под префиксом `/v1` через `RouterModule`, константа `V1_API_PREFIX` в `src/v1/v1-prefix.ts`. Исключение ровно одно: протокол Yggdrasil, чьи пути диктует authlib-injector, они в корне сервера (`/authserver`, `/sessionserver`, `/api`, метадата на `GET /`).

Ошибки собирает `AllExceptionsFilter` (`src/common/`): `HttpException` уходит клиенту как есть, известные 4xx от fastify и multipart пробрасываются со своим статусом, всё остальное превращается в 500 с телом "Internal Server Error". Внутренние тексты в прод не утекают, при этом ошибка полностью пишется в лог.

## Модули

| Каталог                               | Назначение                                                                                         |
| ------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `config/`                             | Zod-валидация env, общие провайдеры, закрытие SQL-пула при остановке                               |
| `memory/`                             | общий in-memory `MemoryDb`: кеш, токены и сессии Yggdrasil, коллекция users                        |
| `cache/`                              | кеш с двумя драйверами за одним интерфейсом: Redis (`REDIS_URL`) или память                        |
| `common/`                             | гарды, декораторы (`@Public()`, `@Roles()`, `@CurrentUser()`), JWT strategy, общие DTO, rate limit |
| `v1/`                                 | контроллеры в трёх группах: `common/` (панель плюс лаунчер), `launcher/`, `panel/`                 |
| `auth/`                               | JWT-токены, ротация refresh, политика паролей, auth-сторы                                          |
| `yggdrasil/`                          | протокол authlib-injector: authserver, sessionserver, текстуры, подписи                            |
| `admin/`                              | пользователи, роли, soft delete, аудит                                                             |
| `technical/`                          | init-owner с bootstrap-токеном, рестарт, rebuild-конвейер                                          |
| `user-content/`                       | скины, плащи, модели: лимиты, активный скин, удаление файлов                                       |
| `files/`                              | манифест файлов игры (chokidar плюс SHA-1), свип служебного мусора при старте                      |
| `launcher/`                           | релизы tauri-plugin-updater, конфиг лаунчера, панельная запись                                     |
| `rcon/`, `minecraft-status/`, `cron/` | RCON-консоль, Server List Ping, фоновые задачи                                                     |
| `utils/`                              | SQL-билдер с диалектами, PNG-валидатор, стриминг файлов, общие хелперы                             |

`DTO` всех запросов и ответов живут в `<module>/dto/dto.ts`, контроллеры их не объявляют. Внедрение зависимостей через DI-токены: интерфейс стора плюс реализации, фабрика модуля выбирает реализацию по env.

## Хранилища

Выбор делает `DB_DRIVER`:

- `map` (по умолчанию): доменные map-сторы над общим `MemoryDb`. Только разработка, в production такой старт валится. В этом режиме auth, admin и Yggdrasil читают одну коллекцию users: регистрация сразу видна панели и протоколу, бан и approve распространяются сами.
- `postgres` и `mariadb`: одни и те же SQL-сторы поверх `Bun.sql`. Диалектные отличия (плейсхолдеры, `RETURNING`, нормализация результата) спрятаны в SQL-билдере `src/utils/sql/`, сторы их не знают. Схема подключения в `DATABASE_URL` переключает диалект.
- `AUTH_PROXY_URL` включает `AuthProxyStore`, заглушку для будущего проксирования авторизации. Чтения пишут warn и не работают, мутации отвечают 501. Не задавать.

Пара свойств, которые полезно знать до чтения кода:

- Токены и сессии Yggdrasil всегда в памяти, независимо от `DB_DRIVER`. Токены живут 15 дней с лимитом 4 на пользователя, сессии 30 секунд.
- Удаление пользователя мягкое: флаг `deleted`, строка и контент держатся 30 дней, потом cron-задача чистит их из БД (файлы скинов и плащей на диске остаются).
- Мутации, затрагивающие несколько записей или два стора, атомарны: сбой шага откатывает уже применённые в обратном порядке.
- Ники совпадают без учёта регистра, два живых одинаковых ника невозможны (партиальный индекс по `lower(username)` при `NOT deleted`), ник удалённого сразу свободен.

## Конфигурация

env валидируется Zod-схемой на старте (`src/config/zod-env.ts`), неверное значение валит запуск с перечнем проблем. Прямые обращения к `process.env` в `src/` запрещены, конфиг читается только через схемы. `SECRETS` принимает JSON-объект и подмешивает переменные, реальное окружение перекрывает его. Сырые значения не попадают в логи при ошибке валидации. Полный список переменных в [setup.md](setup.md).

## Логирование

pino через nestjs-pino. В проде каждая строка пишется в `logs/YYYY-MM-DD.log` и дублируется в stdout, так что `pm2 logs` показывает то же, что и файл. `console.*` в `src/` запрещён: мимо pino логи не попадут в файлы.

Уровни: ответы 5xx и транспортные ошибки на `error`, security-события (отказы мутаций, аудит) на `warn`, причём warn пишется и в проде. Мутации пользователей пишут аудит: актор, его роль, цель, действие. Пароли в логи не попадают никогда.

## Устойчивость к падениям

- `unhandledRejection` логируется, процесс продолжает работу. `uncaughtException` логируется и завершает процесс, pm2 его поднимает (защита от рестарт-лупа считает только быстрые падения).
- Колбэки вотчеров и стримов обёрнуты в try/catch: брошенное исключение внутри EventEmitter стало бы uncaught exception.
- Лог-поток самолечится: удалённый или подменённый логrotate файл пересоздаётся в течение минуты.
- Пул `Bun.sql` закрывается при остановке приложения (`SqlPoolLifecycle`).
- Служебный мусор после павших процессов (temp-файлы загрузок, staging-каталоги релизов и панели) свипается при старте, причём бэкапы из crash-окна сначала восстанавливаются на место и только потом чистятся.
