# Настройка

Пошаговая установка (клонирование, зависимости, `setup:public`, ключи, миграции, сборка, pm2) в README корня репозитория. Здесь справочник по настройке: переменные, драйверы, миграции, первый владелец.

## Требования

- Bun 1.4.2+. Ин-процесс `Bun.cron` требует 1.4, CLI миграций `bunsql-native-migrate` 0.6.1 требует 1.4.2.
- PostgreSQL 14+ для прода. `DB_DRIVER=map` в production запрещён, старт валится.
- MariaDB 10.11+/11.x поддержана SQL-сторами и интеграционными тестами, но миграции в репозитории postgres-only. Поднять новую MariaDB-базу ими нельзя; для нового окружения используйте PostgreSQL.
- pm2 7+ для прод-запуска. Docker пригодится для дев-базы (см. [testing.md](testing.md)).

## Переменные окружения

Значения читаются из реального окружения и из `SECRETS` (JSON-объект), реальное окружение перекрывает `SECRETS`. Валидация Zod-схемой на старте: неверное значение валит запуск с перечнем проблем, сырые значения в лог ошибки не попадают. Минимум для старта: `NODE_ENV`, `JWT_ACCESS`, `JWT_REFRESH`.

| Переменная                 | По умолчанию                 | Описание                                                                                                                  |
| -------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `NODE_ENV`                 | обязательна                  | строго `development`, `test` или `production`                                                                             |
| `PORT`                     | `3005`                       | порт сервера                                                                                                              |
| `LOG_LEVEL`                | `info`                       | уровень pino: `trace`, `debug`, `info`, `warn`, `error`, `fatal`, `silent`                                                |
| `JWT_ACCESS`               | обязательна                  | секрет access-токенов, минимум 32 символа                                                                                 |
| `JWT_REFRESH`              | обязательна                  | секрет refresh-токенов, минимум 32 символа                                                                                |
| `SECRETS`                  | нет                          | JSON-объект с переменными, приоритет у реального окружения. Читает только приложение, CLI миграций его не видит           |
| `DB_DRIVER`                | `map`                        | `map` только для разработки; `postgres` для нового окружения; `mariadb` — сторы поддерживают, но миграции postgres-only   |
| `DATABASE_URL`             | обязательна при SQL-драйвере | строка подключения. Схема (`postgres://`, `mariadb://`, `mysql://`) выбирает диалект SQL-билдера. Держите в `.env`/env    |
| `AUTH_PROXY_URL`           | нет                          | задел на будущее: прокси обычной авторизации. Сейчас включает заглушку, авторизация не работает. Не задавать              |
| `REDIS_URL`                | нет                          | Redis для кеша и rate limit. Не задан: локальная память                                                                   |
| `CACHE_PREFIX`             | `limacina:<NODE_ENV>`        | префикс ключей Redis, изолирует окружения на одном Redis                                                                  |
| `BASE_URL`                 | `http://localhost:3005`      | публичный адрес: текстуры, ссылки, метадата Yggdrasil. В проде укажите реальный домен                                     |
| `MASTER_PASSWORD`          | нет                          | универсальный пароль для любого аккаунта, обходит статусные проверки. Только для отладки                                  |
| `MAX_SKINS_PER_USER`       | `1`                          | лимит скинов на пользователя                                                                                              |
| `MAX_MODELS_PER_USER`      | `1`                          | лимит моделей на пользователя                                                                                             |
| `MAX_CAPES_PER_USER`       | `1`                          | лимит плащей на пользователя                                                                                              |
| `CORS_ORIGINS`             | нет                          | разрешённые домены через запятую, до 100. Не задан: CORS закрыт                                                           |
| `RATE_LIMIT_AUTH_MAX`      | `10`                         | попыток на username (логин, регистрация) за окно                                                                          |
| `RATE_LIMIT_AUTH_WINDOW`   | `60000`                      | окно auth-лимита, мс                                                                                                      |
| `RATE_LIMIT_AUTH_IP_MAX`   | `10`                         | IP-бакет auth-маршрутов, работает вместе с username-бакетом                                                               |
| `RATE_LIMIT_GLOBAL_MAX`    | `600`                        | запросов с одного IP на все маршруты за окно                                                                              |
| `RATE_LIMIT_GLOBAL_WINDOW` | `60000`                      | окно глобального лимита, мс                                                                                               |
| `BEHIND_PROXY`             | `true`                       | `true`: клиентский IP из `X-Forwarded-For` (деплой за reverse-proxy). Прямые подключения: `false`, иначе IP подделывается |
| `TRUST_PROXY`              | нет                          | адрес или подсеть доверенного прокси. Без значения доверяются все. Задан при `BEHIND_PROXY=false`: старт валится          |
| `KEYS_DIR`                 | `./keys`                     | каталог RSA-ключей подписи текстур Yggdrasil. В бинарнике пути считаются от cwd, при другом каталоге запуска задайте явно |
| `MINECRAFT_HOST`           | нет                          | цель пинга для `GET /v1/common/status`: `host`, `host:port` или `[ipv6]:port`. Не задан: эндпоинт отвечает 503            |
| `RCON_HOST`                | нет                          | хост RCON игрового сервера. Без `RCON_PASSWORD` RCON-маршруты отключены                                                   |

`NODE_ENV=production` вдобавок меняет поведение логов: JSON-строки в `logs/YYYY-MM-DD.log` с дублем в stdout, dev-ветка рисует человеческий вывод через pino-pretty.

`JWT_ACCESS` и `JWT_REFRESH` короче 32 символов валят старт. В production обязателен SQL-драйвер и `DATABASE_URL`. `SECRETS` мержится только в конфиг приложения: CLI миграций и дочерние шаги rebuild-конвейера читают реальное окружение, поэтому `DATABASE_URL` держите в `.env` или env, а не только в `SECRETS`.

## Драйверы хранения

`map` держит всё в памяти процесса: удобно для разработки, данные исчезают с рестартом. `postgres` и `mariadb` выбирают одни и те же SQL-сторы, отличие только в диалекте, который определяется схемой `DATABASE_URL`. Домены не знают, на чём работают: у каждого интерфейс стора плюс реализации, фабрика модуля выбирает по `DB_DRIVER`.

У `mariadb` есть ограничение развёртывания: миграции в репозитории postgres-only, поэтому новую MariaDB-базу командами проекта не поднять. Драйвер имеет смысл только для уже подготовленной схемы (например, при переносе существующей базы). Для нового окружения выбирайте `postgres`.

Хранилище выбирается до первого запуска. Переезд с `map` на SQL это перенос данных вручную (аккаунты заново), миграции схему создают, но содержимое памяти не переносят.

## Миграции

Нужны SQL-драйверам. В текущем репозитории миграции поддерживают PostgreSQL; MariaDB-схема ими не создаётся. Тулза: npm-пакет `bunsql-native-migrate`, файлы в `migration/list/`.

```bash
bun run migrate:install   # создать таблицу migrations (up делает это сам, шаг опционален)
bun run migrate:up        # применить все неприменённые
bun run migrate:create имя   # сгенерировать новую миграцию
```

`migrate:up` читает `DATABASE_URL` из реального окружения или `.env`; из `SECRETS` переменная не подхватывается. Прогон останавливается на первой упавшей миграции, изменение уже применённого файла на диске ловится по checksum и прерывает `up`. Файлы миграций руками не создаются, только через `migrate:create`.

## Ключи и статика

```bash
bun run generate:keypair   # keys/ для подписи текстур Yggdrasil, один раз
bun run setup:public       # public/launcher, public/launcher/mods, public/releases, public/textures, public/capes, public/models
```

Без ключей профили Yggdrasil отдаются без подписи, протокол это допускает (в лог пишется ошибка). `public/textures` и `public/capes` наполняются сами при загрузке скинов и плащей. Артефакты релизов лаунчера публикуются через панель в `public/releases/<version>/`, моды кладутся в `public/launcher/mods` вручную или через панель (`/v1/panel/launcher/mods`), их хеши манифест подхватывает сам.

Опционально: `cp config.example.toml config.toml` для дефолтного конфига лаунчера. Его же можно записать через панель: `PATCH /v1/panel/launcher/config`.

## Первый владелец

При старте без владельца сервер пишет файл `bootstrap.token` в корень (права 0600) и печатает токен в stdout. Токен нужен для единственного запроса:

```bash
curl -X POST http://localhost:3005/v1/panel/users/init-owner \
  -H "Content-Type: application/json" \
  -d '{"username": "owner", "password": "securepassword", "token": "<содержимое bootstrap.token>"}'
```

Токен одноразовый, после успеха файл удаляется. Повторный вызов (владелец уже есть) отвечает 409 ещё до проверки токена, так что перебором токен не подобрать. Запрос без поля `token` не проходит валидацию (`400`), неверный токен даёт `403`. Аккаунт владельца используется для входа в панель.

## Панель

SPA панели это отдельный фронтенд-репозиторий, в этом репозитории только её отдача: маршрут `/panel` раздаёт `public/panel/`, каталог создаётся при старте, так что деплой панели рестарта не требует. Сборка и атомарная подмена: `bun run panel:deploy` (аргумент — git ref для отката). Панель ходит в API того же origin, CORS для неё не нужен. Выносите панель на отдельный домен: добавьте его в `CORS_ORIGINS`.

## Redis

Не обязателен. Без `REDIS_URL` кеш и бакеты rate limit живут в памяти процесса. С `REDIS_URL` сбой Redis деградирует, а не роняет API: промах кеша, fail-open у лимитера, переподключение по таймеру. Префикс `CACHE_PREFIX` разделяет окружения на одном Redis.
